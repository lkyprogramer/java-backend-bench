# ReserveLedger / Java Backend Bench v1.0.0：设计与交付计划

## 目标与范围
为本地 Coding Agent 提供一个单题、可重复、低依赖的 Java 后端工程评测。模型在独立工作目录完成库存预占服务；裁判在工作目录外从源码编译、启动、操作和评分。不依赖 Spring、Maven、Gradle、Docker、数据库或第三方 Python 包。

用户要求：后端、优先 Java、连续数小时可完成、开发/测试/边界/性能等多方面考察、每个评分维度满分 10、完整文档与脚本 ZIP。题目以 180 分钟开发预算作为一个建议的固定实验条件，不是模型必定完成的时间承诺。

## 方案选择
普通 CRUD 太容易掩盖并发与状态错误；完整电商系统范围过大且基础设施噪声高；本题选择单节点“库存预占→确认/取消→过期释放”闭环。

只提供 JSON 编解码和带 CRC/force 的日志原语。业务状态、HTTP 协议、参数验证、幂等、并发控制、事件建模、重放、错误处理、分页与测试由模型完成。提供的原语能力不能计作模型独立实现的能力。

## 目录职责
- `candidate/`：唯一允许发给模型的起始工程、冻结辅助类、完整规范、公开冒烟测试。
- `judge/`：裁判、测试目录、性能测量、变异测试、报告和聚合；模型不可读写。
- `reference/`：校准与裁判自检用参考解及缺陷开关；不是待测模型的结果。
- `tests/`：裁判单元测试。
- `bench.py`：环境检查、工作区准备、校准、评分、聚合和完整性检查。
- `tools/`：Agent 计时、顺序批量评分和维护者完整自检。
- `docs/`：操作者手册、分数定义、复现实验、限制与证据。
- `reports/validation/`：本包实际验证记录。

## 实施步骤
1. 冻结 API、错误优先级、时间与恢复语义；定义 10 个自动维度和 2 个独立人工维度。
2. 先写裁判算分测试与黑盒契约测试；在未实现工程上观察失败。
3. 实现独立进程、超时、干净编译、HTTP 测试、随机状态机 oracle 和证据输出。
4. 实现参考解；修复失败但不放松题目契约。
5. 实现性能同机校准和候选测试的变异检验；已知缺陷须被正式测试击中。
6. 自检评分器、无实现/编译失败/超时/缺陷实现、多次参考解运行。
7. 完成中文操作与评分文档、公开包导出、SHA256 清单、ZIP 和实测限制声明。

## 重点风险与约束
- 并发测试检查守恒与线性化允许结果，不能硬编码某个获胜线程。
- 接口响应成功后的数据必须经进程硬终止后恢复；不声称测过断电/磁盘固件可靠性。
- 性能请求必须检查结果；错误响应不能算成功吞吐。
- 候选自测必须先在正确实现上通过，才能计算缺陷检出率；空测试不能因退出 0 获得测试质量分。
- 隐藏测试不得提出公开规范以外的新要求；只有测试数据与组合隐藏。
- 没有执行的强制候选能力项记 0；基础设施故障标明无效，不伪装成模型能力失败。
- 不将 token、成本、GPU 利用率或覆盖率从代码行数估算出来。
- 本地进程执行不是安全沙箱，需独立无敏感信息的账户/机器。
