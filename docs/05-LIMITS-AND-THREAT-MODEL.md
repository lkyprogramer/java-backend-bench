# 能证明什么，不能证明什么

## 本题覆盖

端到端后端开发；精确需求阅读；HTTP/JSON 协议；业务状态与不变量；参数边界；多商品原子性；幂等与重试；并发竞争；时间建模；日志事件设计与重放；故障回滚；分页/统计；对抗常见缺陷的自测；有限负载下的性能与资源；可复现交付。

## 明确不覆盖

真实 Spring Boot/Security/MyBatis/ORM；复杂 SQL 或数据库隔离级别；多节点共识；跨服务事务；完整安全渗透；账号与鉴权系统；前端；真实大型仓库维护；第三方 API 集成；任意机器断电/磁盘损坏；全面代码覆盖率；所有 Java 版本和操作系统；模型长任务的一切能力。

Java HTTP server、JSON 和日志原语的提供降低了模板代码与环境安装噪声，也意味着这部分代码不属于被测模型的原创成果。衡量“从零写 JSON parser”的能力应使用另一道题，不把本题成绩扩大解释。

## 执行与泄漏威胁

普通本地子进程不是安全沙箱。候选 Java/Python 以执行用户权限运行，可能创建线程/子进程、读文件、写磁盘、联网。本包做了最小环境、独立目录、类文件重编译、进程组超时清理和摘要检查，但无法对抗恶意模型在同一用户下篡改裁判、观察 /proc 或盗取答案。

只能在无敏感资料的独立账户/机器上执行；需要强隔离时由外部 VM、容器或操作系统权限负责。不要因为脚本要求 --allow-exec 就以为它已经建立沙箱。生成环境与裁判环境的文件可见性必须实际隔离。

## 测试盲点

80 个场景不是数学证明。随机序列固定 10×120 步，不是穷尽模型检验；并发测试验证设计的竞争性质，不是通用线性化 checker。硬终止是在已应答操作后，不能覆盖每个机器指令或日志字节偏移的崩溃窗口。注入 IOException 发生在 Journal 写入前，不是所有文件系统故障。

测试用例与参考解虽相互独立实现，但仍可能共享规范理解上的错误；独立 oracle 和已知缺陷验证只能降低此风险。应审阅规范与裁判，把发现的问题作为版本化修订，不篡改既有评分。

测试质量使用特定 10 个 API 缺陷族。仅知道这些缺陷而写针对性测试也可能得高分，所以它不是完备的测试工程能力量表；未来版本可增加维护者私有变异族，但必须遵守已公开业务契约并重新冻结题目版本。

## 性能局限

小 HTTP 服务的客户端、JIT、进程启动、温度/频率和本地磁盘都会影响数据。采样 RSS 可漏瞬时峰值；不汇总子进程；Python 负载器可能成为瓶颈。当前读取规模测试是 100→1500 ACTIVE 的局部探测，不能由此推出任意 N 的渐进复杂度。

参考归一化不是行业性能基准。满分意为在容忍带内达到这份参考，而不是已经最优。大量达到 10 分时应提高下一版本负载的区分度，不能在本版本中临时改变标准。

## 成绩含义

自动评分针对交付产物。没有 Agent trace 时，不能推断模型是如何规划、调试、读代码或分配注意力的。维护性与文档质量只能做带证据的人审补充，不能从文件数量自动推断。

Qwen3.8-27B、Qwen3.8-Next 等名称在本包只是由操作者填写的实验对象；本次交付没有运行这些模型，没有给它们编造分数或声称已比较模型能力。
